Как сделать так, чтобы отдельный DHCP-сервер раздавал IP-адреса в три сети на оборудовании  
Cisco, через последовательное подключение роутеров 2911 и коммутаторов 2960 ?  

* Слева - офисная сеть и гостевая.  
* Справа - сеть управления, в которой сидят сисадмины.  
* У всех DHCP от этого сервера.  
* В серверной 2 роутера 2911.  
_____________________________________________________________________________________  

1) Заходим на правый роутер Cisco 2911.  
Это роутер, который смотрит в сеть для системных администраторов.  
Пока что нужно просто поднять интерфейс g0/1.  

en  
conf t  

int g0/1  
no sh  

2) Теперь здесь же, на этом же роутере заходим в сабинтерфейсы,  
поднимаем на них VLANы и накидываем на них IP-адреса.  

// VLAN 10.  
int g0/1.10  
encapsulation dot1Q 10  
ip address 192.168.10.1 255.255.255.0  
no sh  

exit  

// VLAN 20.  
int g0/1.20  
encapsulation dot1Q 20  
ip address 192.168.20.1 255.255.255.0  
no sh  

exit  

// Теперь настроим внешний интерфейс g0/0 на правом роутере. На нём не будет никаких сабинтерфейсов.  
// Он нужен для того, чтобы в последствии развернуть OSPF между сетями.  

int g0/0  
ip address 10.10.10.1 255.255.255.252 (префикс по CIDR: 30)  
no sh  

exit  

4) Теперь сразу, на нём же настроим OSPF, чтобы была динамическая маршрутизация между сетями.  

router ospf 1  
network 192.168.10.0 0.0.0.255 area 0 // Это первая локальная сеть.  
network 192.168.20.0 0.0.0.255 area 0 // Это вторая локальная сеть.  
network 10.10.10.0 0.0.0.3 area 0 // Это наша внешняя сеть. 255 минус 252 = 3, это обратная маска подсети.  

end  

copy running-config startup-config  
Enter  

// На данный момент правый роутер настроен, мы на него вернёмся чуть позже.  

5) Заходим на правый коммутатор в сети системных администраторов (Cisco 2960).  

en  
conf t  

__________________________________________________________________________________________________________________  

int f0/2 // Заходим на интерфейс f0/2. Это интерфейс, который смотрит в сторону РОУТЕРА.  
switchport mode trunk // Его выставляем в режим ТРАНКА.  

exit  
__________________________________________________________________________________________________________________  

int f0/1 // Теперь заходим на интерфейс f0/1. Это интерфейс, который идёт от коммутатора К КОМПЬЮТЕРУ.  
switchport mode access // Его переключаем в режим access  
switchport access vlan 10 // и закидываем в 10 VLAN.  

// Если выскочит ошибка, что VLAN 10 не создан - просто ещё раз вводим команду switchport access vlan 10.  

exit  
__________________________________________________________________________________________________________________  

int g0/1 // Заходим на интерфейс g0/1, он смотрит в сторону DHCP-сервера.  
switchport mode access // Переключаем его в режим access.  
switchport access vlan 20 // И закидываем его в 20 VLAN.  

// Если выскочит ошибка, что VLAN 20 не создан - аналогично ещё раз вводим switchport access vlan 20.  
__________________________________________________________________________________________________________________  

end  

copy running-config startup-config  
Enter  

6) Теперь заходим на наш DHCP-сервер и настроим пулы для раздатки IP-адресов.  

#1.  
Services - DHCP  
Pool name: vlan10  
Default Gateway: 192.168.10.1  
DNS Server: 192.168.20.4  
Service переключаем на ON  
Start IP Address: 192.168.10.5 // С какого адреса будут выдаваться IP-адреса.  
Subnet Mask: 255 255 255 0  
Maximum number of users: 240 // Максимальное количество юзверей.  
Нажимаем ADD, save.  

#2.  
Services - DHCP  
Pool name: vlan30  
Default Gateway: 192.168.30.1  
DNS Server: 192.168.20.4  
Service переключаем на ON  
Start IP Address: 192.168.30.5 // С какого адреса будут выдаваться IP-адреса.  
Subnet Mask: 255 255 255 0  
Maximum number of users: 240 // Максимальное количество юзверей.  
Нажимаем ADD, save.  

#3.  
Services - DHCP  
Pool name: vlan40  
Default Gateway: 192.168.40.1  
DNS Server: 192.168.20.4  
Service переключаем на ON  
Start IP Address: 192.168.40.5 // С какого адреса будут выдаваться IP-адреса.  
Subnet Mask: 255 255 255 0  
Maximum number of users: 240 // Максимальное количество юзверей.  
Нажимаем ADD, save.  

7) Теперь заходим в Desktop - IP Configuration - Static и выставляем статический адрес самому серверу.  

IPv4 Address: 192.168.20.4  
Subnet Mask: 255.255.255.0  
Default Gateway: 192.168.20.1  
DNS Server: 192.168.20.4  

Заодно можем сразу настроить DNS-сервер:  
Services - DNS - DNS Service ON  
Name: dns.com  
Address: 192.168.20.4  
Type: A Record  
Нажимаем ADD, save  

8) Теперь сделаем так, чтобы DHCP раздавал адреса во все наши VLAN-ы справа, т.е. в сеть системных администраторов.  
Заходим на крайний правый роутер Cisco 2911.  

en  
conf t  

int g0/1.10 // Делаем раздатку в 10 VLAN.  
ip helper-address 192.168.20.4  

exit  

int g0/1.20 // И аналогично в 20 VLAN.  
ip helper-address 192.168.20.4  

end  

copy running-config startup-config  
Enter  

9) Заходим на компьютер в сети системных администраторов.  

Desktop - DHCP и проверяем. Должен появиться IP-адрес, маска и DNS.  
Пинги по IP-адресу и DNS-имени также должны работать.  
* С первого раза может выдать APIPA, это нормально, нужно просто переполучить адрес повторно.  
______________________________________________________________________________________________________________  

10) Теперь настроим вторую (двойную) сеть [офисная+гостевая] и будем их связывать по OSPF.  
То есть сеть [офисная+гостевая] будет связана по OSPF с сетью [системных администраторов].  

Заходим на левый роутер Cisco 2911 и для начала просто поднимем внутренний интерфейс g0/1.  

en  
conf t  

int g0/1  
no sh  

11) Дальше, нужно будет поднять сабинтерфейсы.  

// Сначала VLAN 30.  
int g0/1.30  
encapsulation dot1Q 30  
ip address 192.168.30.1 255.255.255.0  
no sh  

exit  

// Теперь VLAN 40.  
int g0/1.40  
encapsulation dot1Q 40  
ip address 192.168.40.1 255.255.255.0  
no sh  

exit  

// Теперь аналогично настроим внешний интерфейс g0/0 для связанности между роутерами по OSPF.  

int g0/0  
ip address 10.10.10.2 255.255.255.252 (префикс по CIDR: 30)  
no sh  

exit  

12) Теперь свяжем наши сети.  

Всё на том же, левом роутере Cisco 2911 пишем:  

router ospf 2 // id процесса может быть любым, 2 просто для примера.  

network 192.168.30.0 0.0.0.255 area 0  
network 192.168.40.0 0.0.0.255 area 0  
network 10.10.10.0 0.0.0.3 area 0  

// Если OSPF свяжется, мы увидим сообщение, которое будет начинаться вот так:  
%OSPF-5-ADJCHG: Process...  
// OSPF может подняться не сразу, нужно какое-то время подождать...  

13) Теперь сделаем так, чтобы DHCP раздавал адреса во все наши VLAN-ы слева.  
 
int g0/1.30 // Заходим на наш сабинтерфейс 1.30  

ip helper-address 192.168.20.4 // и указываем ip-адрес DHCP-сервера.  

int g0/1.40 // И аналогично для сабинтерфейса 1.40.  

ip helper-address 192.168.20.4 // Здесь тоже самое.  

end  

copy running-config startup-config  
Enter  

14) Теперь настроим два коммутатора Cisco 2960 в сети [офис+гостевая].  

Сначала заходим на первый.  

en  
conf t  

int range g0/1-2  
switchport mode trunk // Этими двумя командами мы сразу указываем, что первый коммутатор  
// будет смотреть транком в сторону роутера и в сторону второго коммутатора.  

int f0/1  
switchport mode access  
switchport access vlan 30 // Интерфейс f0/1 выставляем в режим access и закидываем в VLAN 30.  

ex  

// Теперь, чтобы у нас данные передавались ко второму коммутатору, роутер должен знать где находится  
// VLAN 40, но пока он не знает. Как сделать, чтобы роутер узнал? Нужно прописать VLAN 40 на первом  
// коммутаторе относительно левого роутера 2911.  

vlan 40  

// Всё! Этого достаточно!  

end  
copy running-config startup-config  

15) Теперь спускаемся вниз, на второй коммутатор Cisco 2960.  
На нём также нужно будет прописать все транки и аксессы.  

en  
conf t  

int g0/2  
switchport mode trunk  

int f0/1  
switchport mode access  
switchport access vlan 40  

end  

copy running-config startup-config  
Enter  

// Проверяем! Заходим сначала на самый последний ноутбук слева, затем на крайний ноутбук слева.  
// Вкладка Desktop - DHCP, там мы должны увидеть что всё ОК.  

16) Теперь осталось только убедиться, что все всех пингуют по IP и DNS по имени.
