[ Схема 2, GRE over IPSec, она же "Матрёшка". OSPF внутри GRE внутри IPSec. ]  
[ Схема конкретно под Cisco 2911. ]  

_________________________________________________________________________________________________________________  

// Наша схема изначально такая:  

R1 G0/1 = 10.10.10.1  
R2 G0/1 = 10.10.10.2  

R1 LAN:  
192.168.10.0/24  
192.168.20.0/24  

R2 LAN:  
192.168.30.0/24  
192.168.40.0/24  

// На выходе мы должны получить:  

OSPF  
  ↓  
 GRE Tunnel0  
  ↓  
 IPsec  
  ↓  
G0/1  

_________________________________________________________________________________________________________________  

1. R1 — создаём GRE-туннель.  

en  
conf t  

interface Tunnel0 <--- Поднимаем Tunnel0. Здесь должна появиться надпись: changed state to up  

ip address 172.16.100.1 255.255.255.252 <--- Задаём ему IP-шник и самую маленькую маску, на 4 адреса. Здесь IP-шник .1  
 tunnel source GigabitEthernet 0/1 <--- Здесь указываем имя того интерфейса, который смотрит в сторону ПРАВОГО маршрутизатора.  
 tunnel destination 10.10.10.2 <--- Здесь указываем IP-шник ВТОРОГО маршрутизатора. Должно быть написано: changed state to up.  
 tunnel mode gre ip <--- Говорим, чтобы всё это добро работало в режиме GRE.  
 no sh <--- Поднимаем интерфейс.  
ex <--- Выходим.  
ex <--- Поднимаемся до корня.  
copy running-config startup-config <--- Сохраняемся.  
enter  

_________________________________________________________________________________________________________________  

2. R2 — создаём такой же GRE-туннель.  

en

interface Tunnel0 <--- Поднимаем Tunnel0. Здесь должна появиться надпись: changed state to up  

 ip address 172.16.100.2 255.255.255.252 <--- Задаём ему IP-шник и самую маленькую маску, на 4 адреса. Здесь IP-шник .2  
 tunnel source GigabitEthernet 0/1 <--- Здесь указываем имя того интерфейса, который смотрит в сторону ЛЕВОГО маршрутизатора.  
 tunnel destination 10.10.10.1 <--- Здесь указываем IP-шник ПЕРВОГО маршрутизатора. Должно быть написано: changed state to up.  
 tunnel mode gre ip <--- Говорим, чтобы всё это добро работало в режиме GRE.  
 no sh <--- Поднимаем интерфейс.  
ex <--- Выходим.  
ex <--- Поднимаемся до корня.  
copy running-config startup-config <--- Сохраняемся.  
enter  

// Проверяем:  
// С R1 пингуем R2:  

ping 172.16.100.2  

// С R2 пингуем R1:  

ping 172.16.100.1  

// Должно работать. Это мы пингуем уже GRE-шный туннель.  

_________________________________________________________________________________________________________________  

3. Теперь переносим OSPF на GRE.  
// Сейчас OSPF работает просто через G0/1. Нам нужно убрать 10.10.10.0/30 из OSPF и закинуть его в Tunnel0.  

R1.  

en  
conf t  

router ospf 1 <--- Запускаем процесс ospf с id 1. id-шник может быть любой, после этого появится (config-router).  
 no network 10.10.10.0 0.0.0.3 area 0 <--- Убираем эту сеть из OSPF.  
 network 172.16.100.0 0.0.0.3 area 0 <--- Добавляем сеть 172.16.100.0/30 в OSPF area 0  
 network 192.168.10.0 0.0.0.255 area 0 <--- Добавляем сеть 192.168.10.0/24 в OSPF area 0  
 network 192.168.20.0 0.0.0.255 area 0 <--- Добавляем сеть 192.168.20.0/24 в OSPF area 0  
ex <--- Выходим обратно до (config).  

R2.  

en  
conf t  

router ospf 1 <--- Запускаем процесс ospf с id 1. id-шник может быть любой, после этого появится (config-router).  
 no network 10.10.10.0 0.0.0.3 area 0 <--- Убираем эту сеть из OSPF.  
 network 172.16.100.0 0.0.0.3 area 0 <--- Добавляем сеть 172.16.100.0/30 в OSPF area 0  
 network 192.168.30.0 0.0.0.255 area 0 <--- Добавляем сеть 192.168.30.0/24 в OSPF area 0  
 network 192.168.40.0 0.0.0.255 area 0 <--- Добавляем сеть 192.168.40.0/24 в OSPF area 0  
ex  
ex <--- Выходим до корня #.  

// Проверяем:  

show ip ospf neighbor  

// Теперь сосед должен быть через:  

172.16.100.2    Tunnel0  

// а не:  

10.10.10.2      GigabitEthernet0/1  

_________________________________________________________________________________________________________________  

4. Настроим IPsec на R1.  
// Теперь самое важное: IPsec должен шифровать GRE, а не LAN.  

R1.  

conf t  

access-list 110 permit gre host 10.10.10.1 host 10.10.10.2 <--- Разрешаем GRE-трафик между двумя IP.  

license boot module c2900 technology-package securityk9 <--- Включает пакет безопасности SecurityK9.  
// Возможно, эту команду надо будет вбить дважды. Здесь печатаем yes, а НЕ ENTER!!!  

end <--- Выходим до корня.  
copy running-config startup-config <--- Сохраняемся.  
reload <--- Перезагружаем Циску.  

en  
conf t  

crypto isakmp policy 10 <--- Создаём IKE-политику #10.  
 encryption aes <--- Включаем шифрование AES.  
 hash sha <--- Хеширование SHA.  
 authentication pre-share <--- Аутентификация по общему ключу.  
 group 5 <--- Группа Diffie-Hellman #5.  
 lifetime 86400 <--- Время жизни SA: 86400 секунд.  
ex <--- Выходим обратно в (config).  

crypto isakmp key hm902dt-a9142 address 10.10.10.2 <--- Задаём общий секретный ключ (пароль) для соседа с IP 10.10.10.2  

crypto ipsec transform-set VPN-SET esp-aes esp-sha-hmac <--- Задаём параметры шифрования и проверки IPsec.  

crypto map VPN-MAP 10 ipsec-isakmp <--- Создаём Crypto Map.  
 set peer 10.10.10.2 <--- Указываем IP удалённого VPN-пира.  
 set transform-set VPN-SET <--- Используем созданный набор IPsec.  
 match address 110 <--- Применяем ACL 110 для определения трафика VPN.  
ex <--- Выходим обратно в (config).  

interface GigabitEthernet 0/1 <--- Выбираем интерфейс, который смотрит в сторону ВТОРОГО маршрутизатора (config-if).  
 crypto map VPN-MAP <--- Применяем VPN-настройки к интерфейсу. Если всё гуд, появится сообщение, что ISAKMP включён:  
// *Jan  3 07:16:26.785: %CRYPTO-6-ISAKMP_ON_OFF: ISAKMP is ON  
ex  
ex <--- Выходим до корня #.  
copy running-config startup-config <--- Сохраняемся.

6. Проверяем.  

// На R1:  

show ip ospf neighbor  

// Должно быть:  
192.168.30.1      0   FULL/  -        00:00:37    172.16.100.2    Tunnel0  

// Затем:  

show crypto isakmp sa  
 
// Ожидаем:  
10.10.10.2      10.10.10.1      QM_IDLE           1021    0 ACTIVE  

// При том, что мы ничего не пинговали!  

// И:  

show crypto ipsec sa  

// Нас интересуют 4 строчки:  

#pkts encaps: ...  
#pkts encrypt: ...  
#pkts decaps: ...  
#pkts decrypt: ...  

// Там уже должны быть какие-то цифры. Если они есть - значит трафик реально идёт через IPsec!  

// И ACL:  

show access-lists 110  

// Она должна показывать:  

permit gre host 10.10.10.1 host 10.10.10.2  

// Если все четыре проверки пройдены, значит всё круто, мы - молодцы!

// Что получилось?  
// Теперь пакет OSPF идёт так:  

OSPF  
 ↓  
GRE  
 ↓  
IPsec  
 ↓  
10.10.10.1 ───────── 10.10.10.2  

// Или то же самое, но в перевёрнутом виде, снизу вверх:  

                 10.10.10.1                 10.10.10.2  
                     R1 ─────── IPsec ─────── R2  
                      ╲                       ╱  
                       ╲──── GRE Tunnel ─────╱  
                         172.16.100.1/.2  
                               │  
                              OSPF  

// То есть IPsec шифрует GRE-пакет целиком, внутри которого находится OSPF.  
// Именно это и есть GRE over IPsec.
