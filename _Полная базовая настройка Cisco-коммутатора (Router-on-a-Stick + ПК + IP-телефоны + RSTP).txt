Полная базовая настройка Cisco-коммутатора.  

Router-on-a-Stick + ПК + IP-телефоны + RSTP.  

Схема:  
Gi0/1 ---> uplink к маршрутизатору  
Gi0/2-48 ---> пользовательские порты  
VLAN 10 ---> DATA (ПК)  
VLAN 20 ---> VOICE (телефоны)  
VLAN 999 ---> Native / Parking VLAN (BLACKHOLE)  

Как это работает?  
Trunk между коммутом и роутером.  
Маршрутизатор обычно использует схему Router-on-a-Stick.  

Это означает:  
* один физический интерфейс роутера;  
* несколько логических сабинтерфейсов;  
* каждый сабинтерфейс обслуживает отдельный VLAN;  

Чтобы по одному кабелю передавать траф нескольких VLAN, порт коммута переводится в trunk.  

Trunk использует:  
* tagged-трафик для большинства VLAN;  
* untagged-трафик для native VLAN;  
* передачу нескольких VLAN через один линк.  

Native VLAN.  
В trunk-портах существует native VLAN.  

Особенность:  
* кадры native VLAN передаются без тега;  
* по умолчанию это VLAN 1;  
* использовать VLAN 1 как native VLAN - плохая практика;  
* поэтому для него обычно создают отдельный VLAN:  
- например 999;  
- не используют его для пользователей;  
- назначают его как native VLAN.  
* Это повышает безопасность;  
* уменьшает риск VLAN hopping;  
* упрощает администрирование;  
* но само по себе не является полноценной защитой.  

__________ СХЕМА РАБОТЫ __________  
__________ ПОДКЛЮЧЕНИЕ  __________  

РОЗЕТКА ---> IP-телефон ---> ПК  

Телефон умеет разделять трафик:  
* ПК:  
	* untagged  
	* VLAN 10 (DATA)  
* Телефон:  
	* tagged  
	* VLAN 20 (VOICE)  
Для этого на access-порту используется команда: switchport voice vlan 20

ПОГНАЛЕ НАСТРАИВАТЬ:  

1. Переход в режим настройки  
enable  
conf t  

2. Врубаем RSTP  
spanning-tree mode rapid-pvst  

# Зачем он нужен?  
# Для защиты от L2-петель;  
# Для быстрого восстановления сети;  
# Для быстрого поднятия портов.  

3. Включаем QoS  
mls qos  

# Зачем он нужен?  
# Для корректной приоритизации голосового трафика.  
# Чтобы уменьшить задержки, jitter и потери голосового трафика.  

4. Включаем LLDP  
lldp run  

# Что делает?  
# Позволяет телефонам автоматически обнаруживать voice VLAN;  
# Устройствам видеть соседей.  

5. Создаём VLAN-ы  
vlan 10  
name DATA  
exit  

vlan 20  
name VOICE  
exit  

vlan 999  
name UNUSED_NATIVE  
exit  

6. Настраиваем trunk к маршрутизатору через первый порт коммута  
interface GigabitEthernet0/1 # или int gi0/1  

description LINK_TO_ROUTER # описание интерфейса. Можно с пробелами, можно - без.  

switchport trunk encapsulation dot1q # на многих современных Цисках отсутствует и может выдать ошибку: "invalid input detected, или command rejected". Это нормально.  
switchport mode trunk  
switchport nonegotiate # отключает DTP, уменьшает риск случайного trunk, best practice для статических trunk.  
# Это работает только если порт уже переведён в trunk/access вручную.  

switchport trunk native vlan 999  

switchport trunk allowed vlan 10,20 # VLAN-ы перечисляются через запятую, строго БЕЗ пробелов.  

no shutdown  

6.1 Нужно ли включать PortFast на trunk?  
Обычно - нет.  
Почему?  
- trunk может вести на другой коммутатор;  
- PortFast на межкоммутных линках опасен.  
НО!  
Если trunk идёт к роутеру или к серверу, то допустимо ввести команду:  

spanning-tree portfast trunk  

Почему?  
Потому что такие устройства не участвуют в STP и не создают L2-петель.  

7. Настраиваем пользовательские порты.  
interface range GigabitEthernet0/2-48 # или командой int range gi0/2-48  

switchport mode access # переводим весь диапазон портов в режим access  
switchport nonegotiate # уменьшаем лишний L2-мусор.  

# DATA-трафик помещаем в VLAN 10, VOICE-трафик - в VLAN 20.  
switchport access vlan 10  
switchport voice vlan 20  

spanning-tree portfast # убираем STP-задержку. Порт поднимается сразу, ПК получает сеть быстрее. Без этой опции ожидание может быть 30-50 сек.  
spanning-tree bpduguard enable # защита от случайного подключения другого коммута, свитча, петли  

mls qos trust cos # Доверяем CoS-маркировке, приходящей от IP-телефона. Это нужно для приоритета голосового трафика, уменьшения задержек и нормальной работы VoIP  

# Эти две позволяют телефону обнаружить коммут и автоматически узнать voice VLAN  
lldp transmit  
lldp receive  

no shutdown # административно включаем порт  

exit # выход из режима интерфейса  

end  # выход в privileged EXEC mode  

write memory # сохраняемся!
